# Enhancement prompt for bolt.new

Add three features across all pages in the portal.

## 1. "Last updated" timestamp in every page topbar

Every page already has a sticky topbar. Add a "Last updated" element to the right side of each topbar that shows when the page's data was last refreshed.

The data comes from freshness.json (already in the repo). Each page maps to a key:

| Page | freshness.json key |
|---|---|
| index.html | (shows all keys, already does this) |
| medical/index.html | medical |
| steam/index.html | steam |
| jobs/index.html | jobs |
| finance/index.html | finance |
| finance/comp-playground.html | finance |
| email-agency/index.html | email-agency |
| email-digest/index.html | email-digest |
| playgrounds/headache-log.html | medical |
| playgrounds/va-claim.html | medical |
| playgrounds/index.html | playgrounds |
| playgrounds/rapidapi-explorer.html | playgrounds |
| instacart/dashboard.html | instacart |

Format: small text, 11px, faint color, right-aligned in the topbar. Example: "Updated 2026-07-11 19:14". If freshness.json fails to load, show "Updated: unknown".

For the medical page, also check data.json's "generated" field and display whichever is more recent (freshness.json "as_of" or data.json "generated").

For pages that use localStorage (headache-log), also show when the last local entry was added by checking localStorage timestamps.

## 2. "Refresh data" button in every page topbar

Add a small refresh icon or button to the right side of each topbar, next to the "Last updated" text. When clicked:

1. Re-fetch the page's JSON data source(s) without reloading the page
2. Update the displayed data in place
3. Update the "Last updated" text to the current time
4. Show a brief spinner or "Refreshing..." state while fetching

Data sources per page:
- medical/index.html: fetch('medical/data.json') and fetch('medical/bp_log.json')
- jobs/index.html: fetch('jobs/jobs.json')
- steam/index.html: if it fetches a JSON file, refresh that. If inline data, just reload the page
- instacart/dashboard.html: if it fetches a JSON file, refresh that
- playgrounds/headache-log.html: no server fetch needed, but reload localStorage data
- playgrounds/va-claim.html: no fetch needed, static calculator. Button can reload the page
- playgrounds/rapidapi-explorer.html: fetch('playgrounds/rapidapi-catalog.json')
- email-agency/index.html: if it fetches data, refresh that
- email-digest/index.html: if it fetches data, refresh that
- finance/index.html: static, button can reload the page
- finance/comp-playground.html: static calculator, no fetch needed
- index.html: fetch('freshness.json') and update the cards

Use a cache-busting query string to force a fresh fetch: fetch(url + '?t=' + Date.now())

## 3. Doctor export on the medical page

Add an "Export for doctor" button at the bottom of the medical/index.html page. When clicked, it opens a new window with a clean, printable summary view containing RAW FACTS only. No VA claim opinions, no rating estimates, no "va_relevance" fields, no commentary about claim strategy.

The printable summary should include:

### Header
- Patient name: Teon Dexter Moore
- Date of birth: 1991-12-16
- Date printed: (current date)
- Generated by: me.cyberautomations.com/medical

### Section 1: Active diagnoses
Pull from data.json "diagnoses" array. For each diagnosis show:
- Condition name
- ICD code
- Onset date
- Status (active/resolved)
- Diagnosing provider(s)

Omit any field named "va_relevance", "va_claimed", "evidence" (the narrative evidence text), or "onset_basis" (that is claim argument text).

### Section 2: Blood pressure readings (last 90 days)
Pull from bp_log.json. Show a simple table:
- Date
- Reading (systolic/diastolic)
- Source (clinic, home cuff, ED, etc.)

Only show readings from the last 90 days. Sort newest first.

### Section 3: Current medications
Pull from data.json "medications" array. For each medication with status "active" show:
- Medication name
- Brand (if any)
- Dose
- Frequency
- Indication
- Prescriber

Omit any "notes" field that contains VA-related language. Omit "source_set" and "provenance" fields.

### Section 4: Recent encounters (last 6 months)
Pull from data.json "events" array. For events in the last 6 months show:
- Date
- Title
- Category (encounter, hospitalization, lab, imaging, etc.)
- Provider
- Facility

Omit any "va_relevance", "source_set", "source" fields. Omit the "detail" field if it contains VA-related language (search for "va_", "claim", "rating", "DC 7", "service connection").

### Section 5: Providers
Pull from data.json "providers" array. Show:
- Name
- Specialty
- Role
- Facility
- First seen
- Last seen

### Print styling
- Use a clean white background with black text
- Serif font (Georgia or similar) for body text
- 12px base font size
- Section headers in 14px bold
- 1px solid borders on tables
- Page breaks between sections
- 1-inch margins
- A "Print" button and a "Close" button at the top
- No colors, no badges, no accent styling. Plain clinical document.

The button should be labeled "Export for doctor" and placed at the bottom of the medical page, below all existing content. Use a simple button styled with the surface/border/accent design system.

The export function should:
1. Fetch data.json and bp_log.json
2. Filter and format as described
3. Open a new window with window.open()
4. Write the HTML content to it
5. Call window.print() on the new window after a 500ms delay

## Implementation notes

- All changes should be in the existing HTML files, no new files needed
- Keep the unified design system (same CSS variables, same topbar style)
- The refresh button should be subtle, not dominant. Small icon or text button.
- The "Last updated" and "Refresh" elements should be in the topbar-right, stacked or inline depending on space
- Mobile responsive: on small screens, the topbar-right elements can wrap or hide the timestamp and just show the refresh button
